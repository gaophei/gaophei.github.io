# 数据目录迁移实施记录

> 文档范围：Harbor、NFS、MySQL、Oracle 四台服务器的数据目录从系统根盘迁移到新增数据盘，并统一通过 LVM + XFS 管理。  
> 记录日期：2026-09-17 ～ 2026-09-18  
> 当前状态：NFS、MySQL、Harbor 已迁移完成并完成验证；Oracle 已完成迁移前检查，正式迁移待执行。

---

## 1. 变更目标与总体原则

本次四台服务器最初均存在类似问题：业务数据目录直接位于根分区 `/dev/vda1`，新增第二块磁盘后，需要将业务数据迁移到独立数据盘，避免业务增长持续占用系统盘。

统一采用以下原则：

1. 新盘先执行只读检查，确认无需要保留的数据：

   ```bash
   lsblk -f
   wipefs -n /dev/vdb
   fdisk -l /dev/vdb
   ```

2. 新盘采用 LVM 管理，文件系统采用 XFS。
3. 业务路径保持不变，只替换底层文件系统，避免修改应用配置。
4. 涉及数据库、Harbor Registry 等有状态服务时，最终数据同步必须在服务停止后进行。
5. 数据复制统一优先使用：

   ```bash
   rsync -aHAX --numeric-ids
   ```

   以保留 owner/group、权限、ACL、扩展属性、硬链接及数字 UID/GID。
6. 切换后统一使用 UUID 写入 `/etc/fstab`，并执行：

   ```bash
   systemctl daemon-reload
   mount -a
   findmnt <挂载点>
   df -hT <挂载点>
   ```

7. 原数据目录先改名为 `*-old` 保留，用作回退副本；业务验证完成并观察一段时间后再删除。
8. 最后进行服务重启及整机 reboot 验证，确保 LVM 自动激活、文件系统自动挂载、业务自动恢复。

---

## 4.2 LVM/XFS 与挂载

由于 `/opt/nfs/rancher` 当时没有业务文件，可直接创建数据盘并挂到原路径。

实施命令：

```bash

systemctl stop nfs-server

pvcreate /dev/vdb
vgcreate vg_nfs /dev/vdb
lvcreate -n lv_rancher -l 100%FREE vg_nfs
mkfs.xfs /dev/vg_nfs/lv_rancher

mount /dev/vg_nfs/lv_rancher /opt/nfs/rancher
blkid /dev/vg_nfs/lv_rancher
```

`/etc/fstab` 使用实际 UUID，格式：

```fstab
UUID=<NFS_LV_UUID> /opt/nfs/rancher xfs defaults 0 0
```

验证：


## 6.5 迁移设计结论

Oracle 不能只迁 `/u01`。

原因：

- `/u01`：Oracle 软件、ORACLE_HOME、SPFILE、Inventory、FRA、control02；
- `/u02`：全部 datafile、tempfile、redo，以及 control01。

因此正确设计应为：

```text
/dev/vdb 872G
└── PV
    └── vg_oracle
        ├── lv_u01 -> XFS -> /u01
        └── lv_u02 -> XFS -> /u02
```

建议保留一部分 VG free，便于后续在线扩容。当前 `/u01` 仅 7.2G，FRA 上限约 29G，因此可初步考虑 `/u01` 100G；`/u02` 容量应在执行前根据以下命令最终确定：

```bash

du -sh /u02/*
stat -c '%a %U:%G %n' /u02 /u02/oradata
```

若业务规模允许，可参考：

```text
lv_u01  100G
lv_u02  700G
VG Free 约 72G
```

该分配仅为建议值，必须以 `/u02` 实际容量与未来增长预期为准。

若旧目录没有数据，通常无需数据回滚；若后续需要回退，应先停止 NFS 和 provisioner，卸载新文件系统，再恢复原路径。由于当前已经产生 PVC 数据，任何回退操作前必须先备份新 `/opt/nfs/rancher` 内容。

## 7.4 Oracle

1. `shutdown immediate`；
2. 停 listener；
3. 卸载新 `/u01`、`/u02`；
4. 注释 fstab 新条目；
5. 恢复 `/u01-old -> /u01`、`/u02-old -> /u02`；
6. 再启动 Oracle。

# 第六章 迁移后清理原则

旧目录不要在刚完成切换时立刻删除。

建议满足以下条件后再删除：

- 服务启动正常；
- 实际读写测试正常；
- 数据路径、权限、UID/GID 核对正常；
- restart 正常；
- reboot 正常；
- 业务应用验证正常；
- 已经过一个观察窗口且确认不再需要快速回退。
